# Plan: Dynamic Password Policy in Security Tab

## Goal
Update the "Password Policy" section in the Security tab to be dynamic - showing real-time feedback on password requirements as the user types.

## Current State
- Password Policy section (lines 446-476) is **static** - always shows check_circle icons
- Password form fields exist but policy isn't connected to actual input
- Validation happens only on form submission

## Implementation Steps

### 1. Add Password Policy State
Create state to track each requirement's validation status:
```typescript
const [passwordPolicy, setPasswordPolicy] = useState({
  length: false,      // 12+ chars
  uppercase: false,   // [A-Z]
  numeric: false,    // [0-9]
  special: false,    // [!@#$]
  match: false,      // new === confirm
})
```

### 2. Create Policy Validation Functions
Add a function that evaluates new password against all requirements on every keystroke, and a separate function for match checking:
```typescript
const evaluatePasswordPolicy = (password: string) => {
  setPasswordPolicy(prev => ({
    ...prev,
    length: password.length >= 12,
    uppercase: /[A-Z]/.test(password),
    numeric: /[0-9]/.test(password),
    special: /[!@#$]/.test(password),
  }))
}

const evaluatePasswordMatch = (newPwd: string, confirmPwd: string) => {
  setPasswordPolicy(prev => ({
    ...prev,
    match: confirmPwd.length > 0 && newPwd === confirmPwd,
  }))
}
```

### 3. Update onChange Handlers
- Add `evaluatePasswordPolicy(passwordForm.new)` in the `onChange` handler for the new password field
- Add `evaluatePasswordMatch(passwordForm.new, passwordForm.confirm)` in the `onChange` handler for the confirm password field

### 4. Update Password Policy UI
- Replace static check_circle icons with conditional icons based on policy state
- Use `check_circle` (green/secondary) when requirement is met
- Use `cancel` (error) when requirement is not met (after user has typed)
- Add 5th requirement: "Passwords match" (only shows when confirm password has content)

### 5. Files to Modify

  - Add passwordPolicy state (line ~52)

This is a small targeted change - adding reactive state and a validation function, then wiring them together in the existing onChange handler and updating the UI to show real-time status.
